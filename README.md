# CN2 和 IEPL 区别：跨境专线选型、性能对比与 MkCloud 套餐对照

## 公网与内网：CN2 和 IEPL 本质上不是同一类产品

很多用户第一次接触跨境线路时，会把 CN2、IPLC、IEPL 放进同一个篮子比较。实际上它们属于两个不同的层级。先把这一层认知搭起来，后面的性能、价格、适用场景才不会混淆。

业内长期沿用的分类方式是这样的：**IPLC、IEPL、MPLS VPN 都属于内网专线**，走的是运营商点对点切出来的专用通道；而 **CN2 属于公网业务**，是在 ChinaNet（电信 163 骨干网）基础上单独建立的优化网络，但本质上仍然和普通用户共用同一张公网。

这一点直接决定了用户在选择时需要注意的关键差异：

- **物理层**：IEPL/IPLC 在二层或一层就把流量封进私有通道或 MPLS 标签里；CN2 是一种 IP 层的公网 QoS 调度。
- **资源隔离**：IEPL/IPLC 是独占带宽与时隙，与公网完全隔离；CN2 仍然与其他公网用户共用骨干网，只是优先级更高。
- **合规要求**：IEPL/IPLC 主要面向企业合规跨境，资源占用相对稀少；CN2 资源相对充裕，可以面向个人和中小企业。

如果业务对丢包、抖动、跨境稳定性极其敏感（比如金融行情、跨境支付、远程桌面、SLA 合同），内网专线在协议层就有天然优势。如果业务只是日常跨境办公、轻量数据同步或已经接受了"晚高峰可能出现波动"，CN2 在性价比上往往更合适。

## CN2 自身也有三档：163、CN2 GT、CN2 GIA

电信 ChinaNet 骨干网的演进并不是一步到位的。最早的 163 骨干网承担公共流量，里面大约 90% 的国际出口都挤在这一层。后来电信在骨干网之上新建了一张 CN2（AS4809），把国际出口单独走 59.43 节点，称为 CN2 骨干。

CN2 又被进一步切成两档：

- **CN2 GT（Global Transit）**：国内段走 163 骨干网（202.97 节点），只在**国际出口端**走 CN2（59.43 节点）。本质上是「半程 CN2」，价格适中，但 202.97 节点仍会受晚高峰公共流量影响。
- **CN2 GIA（Global Internet Access）**：从国内省级节点开始就全部走 59.43 CN2 骨干网，直到境外出口。延迟更低、丢包更稳，价格也更高，资源稀缺。

判断一段线路是 GT 还是 GIA，常用的方法是用 `tracert` 或 BestTrace 看路由里有没有出现连续的 202.97 节点（GT 标志）、或者全程 59.43（GIA 标志）。第三方文章普遍引用的延迟区间大致是：

| 线路档位 | 典型国内→境外延迟 | 跳数 | 晚高峰丢包 |
| --- | --- | --- | --- |
| 163 普通骨干 | 150–200 ms | 12+ | >10% |
| CN2 GT（半程 CN2） | 120–150 ms | 6–8 | 5–8% |
| CN2 GIA（全程 CN2） | 100–130 ms | 4–6 | 1–3% |

需要注意的是，CN2 GIA 没有「过墙」或加密属性，它解决的是运营商之间骨干网拥塞问题，不等同于翻墙线路。这点在企业选型时经常被混淆。

## IPLC 与 IEPL：都是内网专线，但层级不同

IPLC 的全称是 International Private Leased Circuit，国际私有租用线路，常见做法是在运营商之间建立一条**端到端二层通道**（可以是 SDH/OTN、MPLS 标签、或者 PON 透明传输），中间不经过公网转发。

IEPL 的全称是 International Ethernet Private Line，国际以太网私有线路，可以理解为面向以太网帧的私有专线。和 IPLC 的关键差别主要是承载层：

- **IPLC**：面向业务层 / TDM / SDH，常见于传统运营商国际电路租赁，适合"独占、稳定、跨多城市"的场景。
- **IEPL**：基于以太网帧，通常以 MPLS 标签或 VLAN 方式承载二层透明传输，部署更灵活，价格略低。

二者共同点是：不在公网转发，跳数极少，端内延迟可以在 10–30 ms 之间。差异主要在跨运营商互通的兼容性和成本结构。普通用户在选购时，通常不必区分到 IPLC/IEPL 级别的协议差异，知道"它是内网专线"就够了，需要关注的是带宽档位、入口省份和可用流量。

## 实测性能：CN2 GIA 和 IEPL 在跨境电商、远程办公场景里的差距

公开测评和经验型资料普遍提到的指标差异如下（来自知乎、erdao.net 等技术博客整理的经验值，仅作量级参考）：

| 维度 | IPLC / IEPL（内网专线） | CN2 GIA | CN2 GT |  |
| --- | --- | --- | --- | --- |
| 国内→境外延迟 | 10–30 ms | 40–70 ms | 60–80 ms |  |
| 跳数 | 3–5 | 6–8 | 8–12 |  |
| 晚高峰丢包率 | <1% | 2–3% | 5–8% |  |
| 抖动 | 极低 | 低 | 中 |  |
| 跨境速度（晚高峰） | 接近日常峰值 | 50–80% 峰值 | 30–50% 峰值 |  |
| 价格（同带宽） | 高（内网独占） | 中高（稀缺公网优化） | 中（半程优化） |  |

几个真实场景的体感差别：

- **跨境视频会议 / Zoom / Teams**：CN2 GT 在 19:00–22:00 容易出现周期性卡顿；CN2 GIA 一般流畅；IEPL/IPLC 几乎无感。
- **数据传输 / 跨境 ERP 同步**：CN2 GIA 和 IEPL/IPLC 都可以胜任，IEPL 在大文件持续传输时速率波动最小。
- **远程桌面 / 金融下单**：IEPL/IPLC 抖动最低，更适合对指令到回报链路敏感的业务。

需要注意，这些数字来自经验型整理，不代表任何 SLA 承诺。实际表现还会被云前置、出口服务器、协议（TCP/UDP）等多因素影响。

## 价格差多少：相同带宽为什么能差几倍

公开资料里反复出现的一个比例是：**同带宽下，IEPL 往往贵过 CN2 GIA 几倍**。2024 年 maobuni 测评、2026 年的 CN2/GIA/IEPL 路由对比文章都给出了类似的数字：

- 普通公网 VPS：月付十几到几十元。
- CN2 GIA VPS：月付几百到几千元（同机房档位）。
- IPLC/IEPL 独享套餐：月付几百到上万元（同带宽档次）。

造成差距的不是"运营商定价随便定的"，而是底层成本不同：

- IEPL/IPLC 是物理切片，运营商必须预留光纤 / MPLS 通道给你，资源独占。
- CN2 走公网骨干，仅靠调度优先级换取质量提升，单位带宽成本低得多。

所以选型的取舍逻辑是：**优先评估晚高峰能不能接受 5%–8% 的丢包**，如果不能，直接上 IEPL/IPLC；如果可以，CN2 GIA 是性价比甜点；如果只需要白天用、偶尔丢包也无所谓，CN2 GT 甚至普通 163 就够了。

把线路维度和场景对上，几个常见决策可以这样落地：

**对港业务（华南 / 福建办公、上传下载为主）**
广港 IEPL 共享或独享是主力方向，端内 1–2 ms，独享档对持续大流量更稳。已有云前置网络、希望压低起步成本的用户，深港 IX 上云专线 ¥158/月起更划算。

**对日业务（电商、视频、工具型出海）**
沪日 IPLC 共享档适合中等流量；日方向对带宽稳定性要求高的独享档，月付 ¥600 起，可以脱离晚高峰波动。游戏和直播类业务更倾向独享。

沪美 IPLC 共享适合按流量付费、量级不稳定的初创团队；如果是持续上传数据（备份、长传），建议直接选独享带宽档，月付 ¥800 起。

如果不确定自己属于哪种，可以先用共享流量档测试一两个月，记录晚高峰的丢包率与抖动，再决定是否升独享带宽。MkCloud 升降级通过工单操作，独享降共享差价不退，这是需要注意的成本结构。

## 共享 vs 独享，到底怎么选

看到这里可能有读者会疑问：为什么共享便宜这么多，是不是"阉割版"？其实共享和独享对应的不是质量等级，而是计费资源：

- **共享带宽**：按流量计费，单位时间速率是「峰值」，**不保证持续跑满**。
- **独享带宽**：按 Mbps 持续速率计费，**不保证跑满到任意目标**，但速率更稳定。

二者都可能"瞬时跑得快"，但长时间传输表现差距较大。共享档适合**短时间高峰 + 间歇上传**，独享档适合**持续大流量 + SLA 需求**。MkCloud 的官方知识库明确写到："共享带宽为峰值，不保证持续跑满；独享也不保证 24 小时任意目标满速。"

## 常见问题

**1. CN2 是不是"过墙"线路？**
不是。CN2 是电信在 ChinaNet 之上的公网骨干网优化通道，解决的是运营商之间路由和拥塞问题，不涉及加密或审查规避。选 CN2 不等于解决跨境访问问题。

**2. IPLC / IEPL 是不是一定比 CN2 GIA 好？**
在丢包、抖动、稳定性上一般更好，但价格也是几倍。如果业务对晚高峰波动不敏感，CN2 GIA 已经能覆盖大多数日常需求，没有必须上内网专线。

**3. 怎么验证商家宣传的"CN2 GIA"是真的？**
最直接的办法是跑一次路由追踪，看省级节点到国际出口之间是否完全是 59.43 路由；如果中间出现 202.97 节点，多半是 CN2 GT，而不是 CN2 GIA。也可以用 `whois -h whois.radb.net <IP> | grep origin` 看 ASN 是不是 4809。

**4. MkCloud 的优惠码还能用吗？**

- `MK-8.8`：常规（流量计费）套餐全场 8.8 折，循环优惠。
- `MK-7.8`：独享带宽产品全场 7.8 折首月优惠。
- `MK-NEW`：新客专享价（示例几档新用户套餐）。
- `MK-IEPL-WELCOME` / `MK-IPLC-WELCOME`：分别针对 IEPL/IPLC 的 9 折循环（第三方资料引述）。
- `IXCLOUD`：上云互联优化专线相关优惠（第三方资料引述）。

具体哪些码在当前状态下仍可使用，建议下单前在结算页输入测试一次，再支付。

**5. 共享档跑满后会被限速吗？**
MkCloud 计量型套餐按上行+下行双向统计流量，达到额度后会暂停。可在用户中心自助购买流量重置，或提交工单补差价升级。

**6. 套餐之间可以升降级吗？**
可以，但需提交工单操作，**降级时差价不退**，是否迁移以工单处理结果为准。开通后不支持按"不喜欢地域"退款，只对质量问题提供支持。
